# ID-JAG Standalone LAB

Token exchange with ID-JAG, using a mock authorization server and a sample MCP server. Tier: Demo. Catalog: C1.

## Run and test

```sh
npm ci
npm test                # web, server, resource-as, mcp-sample and script tests
npm run build           # builds the web app
npm start               # http://localhost:4720
npm run doctor          # checks Node, settings and /api/health
npm run reset           # clears run state
npm run check:forbidden # forbidden-strings, UUID and private-host scan
```

Docker: `docker compose -f deploy/docker-compose.yml up --build -d` (publishes 127.0.0.1 only).

## Ports

Server 4720, resource-as 4721, mcp-sample 4722, Vite dev server 4723. Block 4720-4729. Never 8080, 5173 or 18080/19080/19090.

## Mock and live

`MODE=mock|live`, default mock unless the live `PF_*` settings are set, then live (`server/src/mode.js`; the toggle's choice is saved in `DATA_DIR/mode.json`). Mock = the in-process
PingFederate, Acme PingFederate, resource AS and MCP server in `server/src/mock/`, reached only through `server/src/netguard.js` (no other
module may call `fetch`; use `outboundFetch`). Settings are read through `runtimeEnv()`, never `process.env`, so mock mode cannot see real
settings. Mock tokens carry `mock: true`; EC keys use `createECDH` + `createPrivateKey`. Mock sign-in is guarded (`mockSignin.js`).
The server suite runs with `MODE=live` (vitest config); `mock*.test.js` choose mock themselves.

## Diagrams, stories, talk track

- Diagrams are diagram-studio/1 data files in `diagrams/` (one per playground mode: `mock`, `pf-as`, `pf-pf`, `byo`, `gateway-redeem`), loaded by name
  (`web/src/diagrams/loadDiagram.js`) and turned into the page's model by `playgroundModel.js`. Do not hand-build nodes or edges. Edit the
  JSON (box positions, arrows, steps; a step's `why` is its gotcha callout). Arrow handles are chosen from box positions, and a test fails
  when two arrows share a slot or run. The Dockerfile copies `diagrams/` into the web build.
- After any diagram change, run the overlap check in a real browser: evaluate `AI-DEMO-Standalone/scripts/diagram-overlap.js` on `/diagram/<mode>`
  (and `?step=1` to `5`) and expect `pass: true` with no lit label clipped.
- Stories (`web/src/data/stories`) name people only as `{{cast.<id>}}` and nouns as `{{vocab.<key>}}`. Names come from the vertical pack and
  from `customer.config.json` `persona`. A test fails on an undefined token or a written-out cast name.
- `docs/talk-track.md` is the presenter script. A test checks that every bold button name in it still exists in `web/src`.

## Rules that bite

- Mock mode works with no configuration. Live PingFederate use is owner-run.
- No real tenant IDs, internal hostnames, personal names or customer names. Use `.invalid` or `.example` hosts. `npm run check:forbidden` must pass.
- Never commit `.env` files or keys. The one settings file is `~/Development/.env` (mode 600).
- CSS follows `STANDALONE-CSS-STANDARD.md`: tokens only, no colour literals, no `!important`.
- Diagram labels (web/src/utils/idJagLabelPlacement.js) are placed in screen pixels and drawn counter-scaled, so they keep one size at any zoom. Change a diagram or its zoom limit and run the placement tests; no label may cover a box or another label.
- Zoom floor: no diagram zooms out below `READABLE_MIN_ZOOM` (0.9, so card text is 10px or more on screen). Because of it NO diagram's whole map fits its canvas at the overview on a 1440x900 window or a phone (four older maps 1740px wide in the diagram, 1566px on screen at 0.9; gateway-redeem 1140px, 1026px on screen, against a 1022px canvas; a phone canvas is 343x486 at 375x812, 343x399 at 375x667, 358x505 at 390x844; on 1920x1080 only gateway-redeem fits, at zoom 1). Fit and Reset therefore show the floor zoom, not the whole map; the user pans or zooms in. Do not claim an overview that fits. Step views (`?step=N`) and Simulate are cut by the same floor: measured, at 1440x900 20 of the 25 step views leave a lit box not fully in view (23 of 25 at 375x812). README, "Known cost", says so.
- Spacing: the test bound is 120 to 200px between a box and its nearest neighbour (`diagrams.test.js`, tallest card counted as 190px high, a stand-in: real cards are 98 to 185px: 98.2 for the mock browser card, 184.5 for the tallest); the gaps computed that way are 130 to 190px in the four older diagrams and 120 to 150px in gateway-redeem (README says the same). Every box's position is pinned too (`LAYOUT` in `diagrams.test.js`). Boxes sit close so a 100px by 60px drag on screen leaves every arrow a route.
- Dragging: `autoPanOnNodeDrag={false}` on the diagram's ReactFlow. With it on, React Flow pans the view while a box is held near the canvas edge (a 343px phone canvas is nearly all edge), so the box lands further than the pointer moved, often on another box. A test pins the prop for every mode; the browser check is to drag every box by (100,60) and (-100,60) at 375px and 1440px and run the overlap check. A dropped box never refits the view. A box released over a DISABLED button (Next on the last step, Back on the overview: under the canvas on a phone, beside it on a desktop) used to stay stuck to the pointer: Chrome sends no `mouseup` to a disabled control, and React Flow ends a drag on the window's `mouseup`. Root cause found by logging the events of a stuck drop (`pointerup` on the disabled `Next ▶`, no `mouseup`). The fix is `pointer-events:none` on `.ijx .sim button:disabled` (React Flow does the same for its own disabled zoom button). Tests: a jsdom guard in `IdJagDiagramLegibility.test.jsx` (every disabled control on every diagram page, overview and last step, has `pointer-events:none`) and the browser check `python3 scripts/check-diagram-drag-release.py --base http://127.0.0.1:<port>` (needs the build served and Python Playwright; it drags a box onto the disabled button in every mode at 1440x900 and 375x812 and fails if the box stays in React Flow's dragging state or follows the pointer afterwards).
- An arrow the router cannot route (a box dragged hard against another) is drawn as a plain orthogonal line from `plainRoute` with a badge only (no words; origin/main drew no badge for it). The badge sits clear of every box when the gap is 24px or more (Chrome: 0px from 25px, at most 0.3px at 24px). Below that nothing fits and a SEPARATE finer pass in `placeLabels` (`choose`) puts it near the middle of the gap: it runs only for a badge alone (no words showing) whose coarse spot touches the air kept around a box (a real box: the tool buttons and zoom controls in `avoid` never trigger it, and keep their plain "nothing under a button" rule inside it), and offers the middle of every run and a cost that follows how far the circle reaches into the real box (a spot wholly outside the canvas costs like one cut by its edge). Measured in Chrome (mock diagram, one arrow, gaps 20 to 40px, zooms 0.9, 1.08, 1.3, 102 gaps per tree): reach into a box at most 2.0px sideways / 2.3px vertically at a 20px gap, 1.5 / 1.8 at 21px, 1.2 / 1.7 for 22 to 24px (vertically the badge centre sits 0.25 to 1.2px off the middle of the gap; React Flow measures box heights in whole pixels, 98 for a 98.19px card and 115 for 115.45, which is a likely cause, not proven), 0.0 / 0.3 at 24 to 25px, 0 from 25px. origin/main on the same page: 7.0 to 9.7px at 20 to 24px, up to 7.9px at 26 to 29px (a second measurement: 9.9px at 22px, 12px at 20px). Known limits, documented in the README: two arrows between the same boxes in a 26 to 29px gap overlap each other by up to 3.75px (90px-high test boxes; main put them 12px into a box); under 20px the badge dips about (24 - gap) / 2 (2.8 to 5.3px measured at gaps of 14 to 19px; centre on a box edge at 0 to 6px, where main reached 8.7 to 11.9); an unrouted arrow in a 20 to 23px gap gets a badge reaching up to 2.0px where main had none. Everywhere else the placement is exactly origin/main's: measured in node, main against this branch, with the buttons and zoom controls as measured in Chrome at 5 viewports (zooms 0.9 to 1.5, random pans, both layouts): 0 of 18,000 shipped-diagram scenes differ per layout, no `ok` lost or gained, no badge newly cut by the canvas edge, no new reach into a box; a test pins a digest of 1,272 placements and one pins a button over the arrow. In 27,072 synthetic scenes (gaps 20 to 219px) 4,232 differ (gaps 20 to 47px), `ok` lost 0, gained 0. Tests: `FlowEdge.test.jsx` (the draw path), `idJagPlaygroundRouting.test.js` (the line), `idJagLabelPlacement.test.js` (placement, narrow gaps, and one pin per boundary of the finer pass).
- Card text size is pinned by `web/src/pages/__tests__/cardCssScan.js`, used in `IdJagDiagramLegibility.test.jsx`. What it does: it reads the app's stylesheets (`appStylesheets`: every `.css` under `web/src`, every `.css` a script under `web/src` imports with a literal path (`import "../x.css"`, `import("...")`, `new URL("...")`) and every `.css` another `@import`s, as long as the file is inside `web/` and not under `node_modules`; plus the `<link rel="stylesheet">` files and `<style>` blocks of `web/index.html`) and the rules in them (rules in `@media`/`@supports`/`@layer`/`@container`/`@scope`, native nesting with `&`, bare nested selectors and nested `@media`; at-rule statements such as `@layer a, b;` are skipped). For each selector it asks the DOM (`element.matches`) whether it can match the first card of the mock diagram, anything inside it, or any element above it up to `html`, in every card state (each kind in the five diagrams, dim, on, sel; node selected or dragged). `:hover`, `:focus`, pseudo-elements and structural pseudo-classes (`:nth-child`, `:last-child`) count as always on, and an unknown pseudo-class (`:lang()`) is dropped. Page state is assumed possible on the ancestors: attributes in a selector's earlier compounds (`:root[data-theme="dark"]`, `[data-id="pf"]`) are set on every ancestor, and so are classes and ids no element carries (`html.dark`, `body.presenter`), and a `:root[...]`/`html.x`/`body.x` last compound. A matching `font-size` (or the size in `font`) must be at least 10px on screen at the floor zoom: px and rem (rem from the smallest root size any state sets, e.g. the presenter scale), em and % only on `html`/`body`, `calc()`/`min()`/`max()`/`clamp()` and `var()` of custom properties declared in the CSS are evaluated; anything else fails as unreadable. Property names written with CSS escapes (`font\2d size`) are decoded and lower-cased, and an animation name may be quoted or escaped (`animation-name:"sh"`, `@keyframes "sh"`), every name in a list is followed. Any `zoom`, `scale`/`matrix` transform, `scale` property, `text-size-adjust` (other than none/auto/100%) or `font-size-adjust` on a matching rule fails, also inside an `@keyframes` the rule names in `animation`. Tests: `cardCssVariants.js` holds 116 CSS snippets that must fail it and 36 that must not; `IdJagDiagramLegibility.test.jsx` also tests the stylesheet loader (a `.css` outside `web/src` imported from a script or by `@import` is scanned) and each helper on its own.
- Card text scan, over-reports on purpose (kept, and documented): any `zoom` or `scale` above 1 (`zoom:1.2`, `scale(1.2)`, `scale:1.5`), identity forms other than `1`/`none` written another way (`matrix(1,0,0,1,0,0)`, `scale(100%)`, `scale:1 1`), physical units (`12pt`, `1pc`, `.5in`, which it cannot turn into px), and a small size or a shrink in a rule for a class or element the fixture does not render (`.refs li` on a step page's list, `.react-flow__minimap *`), which the scan reads as if that class sat on an ancestor of the card. Real CSS passes.
- Card text scan, NOT covered: a stylesheet that is not a literal path (`import(`./${name}.css`)`), is outside `web/`, or is under `node_modules` (React Flow's own, `@fontsource`'s; React Flow's holds font sizes only for its attribution, edge text and default node types, which a card does not use); sibling selectors that need an element the fixture lacks (`input:checked ~ .ijx .cs` reads `input` as an earlier sibling that is not there, so it is not flagged); inline styles and styles set from JS (customer config sets CSS variables with `setProperty`; `--present-scale` set at runtime); React Flow's own stylesheet (in `node_modules`); the cascade and specificity (every matching rule counts, `!important` and `@layer` order are ignored, a media or container condition is never evaluated: conservative on purpose); only the first card of the mock diagram is rendered, so another card's own content or attributes are reached only through the ancestor and structural relaxations above (`:has()` and attribute rules on the card itself are checked against that one card); a card kind or class no diagram uses (a `k-new` rule) and a card state beyond kind, dim, on, sel, selected, dragging; page state needing a mix of tokens (`.a:not(.b) .cs` is tried with none and with all of its ancestor tokens set, not each combination); any selector jsdom's engine silently reads as no match beyond the ones normalised (escapes, upper-case tags, legacy `:before`, unknown pseudo-classes); an `em`/`%` size on anything but `html`/`body` (fails as unreadable, so over-reported, not missed); a keyframes name supplied through `var()`; things that shrink text without `font-size`, `zoom`, `scale`, `transform: scale`/`matrix` or `text-size-adjust` (a `perspective()` or `translateZ` transform, `filter`, `contain`).
- Node 26 only (engines, Dockerfile and CI).
